# Qué hacen los exploradores web

Internet ofrece muchísimos recursos e información a todos los usuarios. La forma más común de interactuar con estos recursos y esta información es a través de un explorador web.

 El marcado envuelve el contenido del sitio web con instrucciones que describen a los exploradores cómo visualizar la información. Por ejemplo, en el siguiente marcado, los corchetes y las letras fuera de la frase indican al explorador web que muestre en negrita la frase "El desarrollo web es divertido":

<b>El desarrollo web es divertido</b>

El explorador web visualiza, o representa, la información. Representación es cuando el explorador interpreta el marcado para dar formato al contenido y visualizarlo a los usuarios.

## La experiencia en el explorador web

En los inicios del desarrollo de los exploradores, algunos exploradores no seguían los estándares, por lo que los desarrolladores web tenían que escribir contenido web para acomodar todas las variedades de marcado que esperaban los exploradores. Hoy en día, las empresas se alinean estrechamente con los estándares aceptados, por lo que los desarrolladores web pueden centrarse en escribir un buen código.

### Estructura de documento

Cuando un explorador lee un documento HTML, busca secciones que describan cómo procesarlo. En inglés, las oraciones suelen tener un sustantivo, un verbo y un objeto. Cada uno de estos elementos cumple una función en la oración. 

## Conozca la estructura de las etiquetas HTML

La estructura de documento contiene una estructura adicional de etiquetas. Las estructuras de etiquetas incluyen instrucciones entre corchetes angulares. Un elemento se compone de una etiqueta de apertura y de una etiqueta de cierre. La mayor parte del contenido de los documentos HTML se coloca dentro de los elementos.

## Método en cascada vs. método ágil del desarrollo

- Ciclos largos. Como cada fase del enfoque puede llevar mucho tiempo, el proceso completo puede tardar meses, o incluso años, en completarse. Cuando los proyectos se hubieran completado, el producto que habrían desarrollado podría estar obsoleto.

- Menos interacción con el usuario: con el enfoque en cascada, los usuarios solo intervienen al principio de la fase de planificación para recopilar requisitos y hacia el final del proyecto. Esto significa que las necesidades de los usuarios solo se determinan al principio del proyecto, y si sus necesidades cambian a lo largo del mismo, esas necesidades no se tendrán en cuenta. 

- Aplazamiento de las pruebas hasta el final: como las pruebas se realizan al final del ciclo, es posible que el equipo no detecte los problemas hasta que se haya realizado gran parte del trabajo. Dependiendo de la magnitud de los problemas, las soluciones pueden resultar costosas y retrasar el lanzamiento del proyecto.
